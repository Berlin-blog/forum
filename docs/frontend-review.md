# 前端体验评估与优化建议

> 评估对象：Berlin-blog/forum  
> 评估时间：2026-11-25  
> 线上：<https://berlin-blog.github.io/forum/>  
> 当前规模：8 个用户、10 个主题、35 条可见帖子、11 个吧、46 个称号
>
> 评估过程中顺手修复了两个已发现的问题：个人主页过滤软删除内容、首页精选排除机器人内容。下文的移动端导航仍是当前最优先建议；个人主页/精选两条保留为“已修复记录”。

---

## 1. 总体结论

**视觉方向已经成立，产品信息架构也基本完整；当前主要问题不是“再做一个新页面”，而是“把已有页面做得更顺手、更像一个成熟社区”。**

综合评分：

| 维度 | 分数 | 说明 |
|---|---:|---|
| 视觉识别 | 8/10 | 象牙白 + 古铜金、东方编辑感，辨识度高 |
| 信息架构 | 7/10 | 首页、吧、主题、个人主页、搜索、设置、榜单齐全 |
| 桌面体验 | 7/10 | 层级清楚，但部分页面卡片重复、留白偏多 |
| 手机体验 | 5/10 | 已有响应式，但顶部导航在 390px 下明显拥挤、换行 |
| 交互完整度 | 7/10 | 发布、回复、编辑、删除、关注、通知都有；点赞/举报等 UI 仍缺 |
| 内容运营 | 5/10 | 有机器人热点，但人味、精选感和社区氛围仍不足 |
| 可访问性 | 5/10 | 有 focus 样式和减少动效；弹层 focus trap、语义标签仍缺 |
| 性能 | 6/10 | 首页已聚合、移动端有优化；公网仍受 ngrok 延迟，首屏无骨架屏 |
| **整体** | **6.5/10** | **可用的社区 MVP，视觉强于交互细节** |

---

## 2. 做得好的地方

1. **视觉有记忆点**  
   首页的宣纸底、印章、金线、编辑式排版，和常见论坛模板差异明显。

2. **设计 token 统一**  
   颜色、边框、字号、阴影都集中在 CSS variables，夜间模式也能复用。

3. **首页已从“空泛 hero”变成内容页**  
   精选、本周清谈、正在发生、游园、清谈榜、今日课业、每日一记，信息层次比早期完整很多。

4. **新功能有统一入口**  
   设置、称号墙、周榜、通知、吧主后台都能在既有导航/个人主页中找到。

5. **细节考虑**  
   草稿自动保存、图片预览、未读红点、限时称号、减少动效、夜间模式，都是超出普通 MVP 的细节。

---

## 3. 当前最明显的问题

### 3.1 手机顶部导航拥挤（P0）

390px 宽度下：

- `首页`、`吧广场` 被挤成两行；
- `搜索 / 设置 / 铃铛 / 用户 / 退出` 全部挤在一行；
- 视觉上像“被压扁的桌面导航”。

建议：

- **移动端不要保留桌面横向导航**；
- 改成底部 Tab：`首页 / 吧 / 搜索 / 通知 / 我的`；
- 设置放进「我的」或头像菜单；
- 顶栏只保留品牌、页面标题、必要操作；
- 底部 Tab 高度 56–64px，适配 `safe-area-inset-bottom`；
- 触控目标不小于 44px。

这是当前最值得优先做的移动端改造。

### 3.2 个人主页曾展示已删除的测试帖（已修复）

评估时个人主页曾出现：

- `UI删除测试帖`
- `删除回复测试帖`
- `草稿编辑删除测试帖`
- `编辑删除接口测试帖（已改）`

原因：个人主页查询只按 `author_id` 取主题/回复，没有过滤：

```sql
status = 'open'
deleted_at IS NULL
```

同时统计数字也把这些软删除内容算进去了。

这会直接破坏用户对“删除”功能的信任。建议：

1. 主页主题/回复/统计全部过滤 `status` 和 `deleted_at`；
2. 清理已经软删除的测试数据；
3. 删除后从个人主页、搜索、本周榜、首页统计同步消失。

### 3.3 首页“今日雅集 / 本周清谈”曾被机器人内容占据（已修复）

评估时首页首屏的“今日雅集·精选”和“本周清谈”第一条，曾都是：

```text
【热点】《丑狐》凭什么让全网催更
@hotbot · 0 回复
```

问题不是机器人不能上首页，而是：

- 它被呈现为“编辑精选”，但没有编辑判断；
- 同一篇内容在 hero 卡和本周清谈里重复出现；
- 0 回复的机器人聚合内容压过了真人讨论。

建议：

- 机器人内容加明显 `机器人 / 热点播报` badge；
- 精选优先 `is_featured` 或“有人回复/有人点赞”的真人主题；
- fallback 不要直接用最新一条；
- hero 卡和“本周清谈”去重，同一篇最多出现一次；
- 机器人热点单独做「今日热点」横向条，而不是占“雅集精选”。

### 3.4 加载态太“素”（P1）

周榜切换、主题页、搜索页在慢网下会出现：

```text
加载中...
```

然后是一大片空白。

建议：

- 给首页、榜单、主题列表、搜索加 skeleton（骨架屏）；
- 保持页面结构不跳动；
- 空状态和加载状态分开，不要用同一块空白。

### 3.5 长列表的入场动画会拖慢内容出现（P1）

称号墙有 46 张卡，每张有 `animationDelay`；截图时后半部分会处于半透明/未出现状态。

建议：

- 超过 12 项的网格不要逐项延迟；
- 只对首屏 6–8 项做 stagger；
- 或使用 `content-visibility` + 轻量 fade；
- 尊重「减少动效」设置。

### 3.6 称号墙缺少筛选（P1）

46 个称号一次性铺开，用户很难找到：

- 我还差什么条件？
- 哪些是限时？
- 哪些是等级称号？
- 哪些是行为称号？

建议增加：

- `全部 / 已解锁 / 未解锁`
- `等级 / 行为 / 周榜限时`
- 搜索称号名
- 已佩戴/收藏标记
- 顶部显示「已解锁 4 / 46」和下一目标

### 3.7 搜索页缺少“搜索工具”的感觉（P1）

现在只有：

- 关键词
- 全部 / 主题 / 吧 / 用户
- 结果列表

缺少：

- 搜索历史
- 热门搜索
- 按吧 / 作者 / 时间过滤
- 结果高亮
- 空结果推荐
- 快捷键 `/` 聚焦
- 结果分页的页码/总数展示

而且无结果时页面空白很大。建议把空结果变成「最近热搜 / 推荐吧 / 发一帖」。

### 3.8 主题页缺少社区常用动作（P1）

当前主题页有编辑、删除、回复、楼中楼，但缺少：

- 点赞按钮（后端已经有 `POST /api/posts/:id/like`，前端没接）
- 引用回复
- 楼层锚点 / 复制链接
- 回到顶部
- 图片 lightbox
- 移动端底部固定回复栏
- 回复排序（正序/倒序）

其中**点赞 UI 缺失**最可惜，因为接口已经存在。

### 3.9 弹层可访问性不足（P1）

关注列表弹层：

- 没有 `role="dialog"` / `aria-modal`
- 没有 Escape 关闭
- 没有 focus trap
- 遮罩点击关闭是好的，但键盘用户无法完整操作

建议统一做一个 Modal 基础组件。

### 3.10 视觉上“卡片太多、层级太平均”（P1）

当前大量模块都使用：

- 同一张米色渐变
- 同一圈细边框
- 同一个圆角 3px
- 同一个内边距

看久了会像“一页卡片叠卡片”。

建议：

- 一屏只保留 1–2 个真正的“卡片”；
- 其他模块用分隔线、留白、编号、侧栏色块；
- 主标题和正文之间拉开字号差；
- 首页 hero 可以更“杂志封面”，信息少一点、标题更大一点；
- 机器人内容用不同的“来源条”样式，而不是普通帖子卡。

## 4. 页面级建议

### 首页

- 移动端底部导航
- 精选去重
- 机器人内容独立「热点」带
- hero 卡增加摘要/标签/阅读时长
- 「正在发生」支持“只看真人/只看热点”
- 骨架屏
- 首页统计增加“今日新帖/今日回复”，比总用户数更有活力

### 吧页

- 吧头像/封面图
- 吧规折叠
- 置顶/精华/最新筛选
- 吧成员/吧主入口
- 主题列表行高压缩，移动端一屏多显示 1–2 条
- 空吧态引导发帖

### 主题页

- 点赞、引用、楼层链接
- 图片 lightbox
- 回复框固定在移动端底部
- 楼层分页 + 跳楼
- 楼主标识、机器人标识
- 已编辑/已删除状态更清楚

### 个人主页

- 顶部 cover/banner
- 主题/回复/称号/成就 Tab，避免一次性拉太长
- 关注/粉丝点击弹层
- 加入时间、最后活跃
- 置顶主题/代表作
- 删除内容过滤
- 称号选择器支持搜索/筛选

### 称号墙

- 分类筛选 + 搜索
- 已解锁优先
- 限时称号显示到期时间
- 已佩戴/可佩戴状态
- 进度条/下一目标

### 周榜

- 骨架行
- 显示上一周结算结果
- 显示下周结算倒计时
- 前三名显示限时称号样式
- 周榜规则可折叠说明
- 空周榜态给“本周还没有人上榜”

### 设置

- 分组：阅读 / 外观 / 通知 / 隐私
- 主题预览（日间/夜间缩略图）
- 字号/行距选项
- 更细的通知偏好
- 设置变更即时预览

### 搜索

- 搜索历史、热门词
- 结果高亮
- 过滤器
- 空结果引导
- 搜索框快捷键

### 通知

- 按日期分组
- 类型图标区分回复/关注/等级/吧务
- 未读全部/单条操作
- 空状态引导

## 5. 设计系统建议

### 字体层级

当前标题和正文对比不错，但还需要：

- 页面标题：32–40px
- 区块标题：20–24px
- 卡片标题：16–18px
- 正文：14–15px
- 辅助：11–12px
- 不要所有模块都用同一种“标题 + 说明 + 边框”

### 色彩

- 白天：继续象牙白 + 古铜金
- 夜间：已验证可用，但部分按钮/边框对比偏低
- 增加一个“强调色”只用于主操作（发帖/回复/签到），不要让金色出现在所有地方
- 机器人/热点用独立色条（如深青或朱砂），和真人内容区分

### 组件

建议抽出：

- `PageHeader`
- `SectionHeader`
- `Card` / `Surface`
- `EmptyState`
- `Skeleton`
- `Modal`（含 focus trap）
- `Tabs`
- `Badge`（机器人/楼主/精华/限时）
- `LoadMore`

这样新页面不会继续复制 CSS。

## 6. 性能建议

1. **路由级 lazy loading**  
   设置、称号墙、周榜、吧主后台不需要进首屏 bundle。

2. **骨架屏**  
   首页/榜单/主题页在 API 未返回时保持结构。

3. **图片**  
   当前图片以 data URL 内嵌，带图主题会变大；长期建议对象存储/CDN，短期至少做缩略图和 lightbox。

4. **公共接口缓存**  
   首页、榜单、称号墙可加短 TTL 缓存或 ETag。

5. **长列表**  
   称号墙/搜索结果/主题列表使用 `content-visibility` 或虚拟列表。

6. **移动端减少持续动画**  
   已有关闭金尘的选项，但默认移动端也应更克制。

---

## 7. 可访问性建议

- Modal：`role="dialog"`、`aria-modal`、Escape、focus trap
- 所有图标按钮加 `aria-label`
- 图片 `alt` 不要只写“图片”，允许用户填写描述
- 导航加 skip link
- 减少动效设置已经存在，继续保持
- 夜间模式检查文本对比度
- Tab 键顺序和焦点环要覆盖所有可交互元素

---

## 8. 优先级路线

### 立即（1–2 天）

1. 移动端顶部导航改成底部 Tab
2. 修个人主页已删除内容/统计
3. 首页机器人内容不占“精选”，去重
4. 周榜/主题/搜索加骨架屏

### 近期（1 周）

5. 点赞、引用、楼层锚点、图片 lightbox
6. 称号墙筛选 + 搜索
7. 搜索历史/热门/过滤/高亮
8. 个人主页 Tab 化

### 中期（2–4 周）

9. 设计系统组件化
10. 移动端固定回复栏
11. 关注动态流 / 通知偏好
12. 性能：路由 lazy、图片 CDN、接口缓存

---

## 9. 最值得先做的三件事

如果只做三件事：

1. **移动端底部导航**  
   直接解决当前最明显的“挤压感”。

2. **修个人主页的删除过滤 + 首页精选去重**  
   一个是数据可信度，一个是内容品质感。

3. **补齐主题页的点赞/引用/图片查看**  
   让主题页从“能看”变成“愿意互动”。

---

## 10. 结论

这个项目现在的视觉已经不像一个普通 MVP，**它的问题主要在“最后一公里”的移动端和信息密度**，而不是缺少大功能。

优先做：

- 移动端导航
- 删除数据一致性
- 首页内容编排
- 主题页互动
- 称号/搜索的筛选

做完这五项，整体体验会从“精致的个人项目”提升到“可以日常使用的社区产品”。
